## 1. Product summary

One URL per family: `https://<site>.pages.dev/?g=<guestId>`.

- WhatsApp preview shows the family's name in the title.
- Opening: temple doors open on tap, conch sound, Ganesh line-art draws itself, petals fall, the
  family's name and the couple's names reveal.
- Scrolling tells the invitation: parents' invitation text, couple, story, countdown, the
  functions this family is invited to, interactive rituals (saat phere, varmala, mehendi, haldi),
  gallery, RSVP per function, shagun (UPI), blessings wall, travel/stay, contacts, closing.
- The site changes by date: **pre** (invite), **live** (wedding days: "Now happening"),
  **post** (thank-you + photo album).
- Admins get `/admin/`: headcounts per function, food split, who opened, who hasn't replied,
  one-tap WhatsApp send per guest.

## 2. Architecture

```
Guest phone ──GET /?g=ID──▶ Cloudflare Pages
                              │ functions/_middleware.js
                              │  - looks up ID in bundled guest map (functions/_data/guests.js)
                              │  - rewrites og:title / og:description
                              │  - injects <script id="guest-data" type="application/json">
                              ▼
                           dist/index.html + assets (static, CDN)

Guest phone ──POST (rsvp / wish / open)──▶ Apps Script web app ──▶ Google Sheet
Admin page  ──POST (admin.*)────────────▶ Apps Script web app ──▶ Google Sheet

Sheet menu "Shubh Vivah ▸ Publish guest list" ──UrlFetch──▶ Cloudflare Deploy Hook
   └─▶ Cloudflare build runs `npm run sync-guests` (GET ?action=export) then `vite build`
```

Why the guest map is bundled into the edge function instead of fetched per request:
- Zero extra latency on page open and on WhatsApp's crawler (which times out quickly).
- Apps Script cold starts (1–2 s) never touch page load; Apps Script is used only for writes and
  admin.
- Files under `functions/` are not served as static assets, so the name list is not public.

## 4. Data

### 4.1 `content/wedding.json`

The full example with every field is in `content/wedding.json` (delivered alongside this spec).
Rules:
- Every text field is `{ "hi": "...", "en": "..." }`.
- All datetimes are ISO 8601 with `+05:30` offset.
- `events[].id` is one of: `tilak`, `haldi`, `mehendi`, `sangeet`, `baraat`, `phere`, `vidaai`,
  `reception` (extendable; the id is what the Sheet uses in `allowed_events`).
- `events[].motif` selects the event card illustration and special effect:
  `haldi` → splash wipe (§7.6), `mehendi` → mehendi reveal (§7.7), others → standard card.
- Optional blocks (`story`, `gallery`, `shagun`, `travel`, `livestream`, `postWedding`) are
  hidden if absent or `"enabled": false`.

## 5. API contract (Apps Script web app)

Single URL: `https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec` (stored in `.env` as
`VITE_API_URL` and in Cloudflare env as `APPS_SCRIPT_URL`).

### 5.1 Transport rules (important — avoids CORS failures)

- **GET**: query parameters, no custom headers.
- **POST**: `fetch(url, { method: "POST", body: JSON.stringify(payload),
  headers: { "Content-Type": "text/plain;charset=utf-8" }, redirect: "follow" })`.
  `text/plain` keeps it a "simple request" so the browser sends no preflight (Apps Script cannot
  answer OPTIONS). Code.gs reads `JSON.parse(e.postData.contents)`.
- **Open ping**: `navigator.sendBeacon(url, new Blob([json], { type: "text/plain" }))`, fire and
  forget.
- Every response: `ContentService.createTextOutput(JSON.stringify(obj)).setMimeType(JSON)`.
  Shape: `{ "ok": true, "data": ... }` or `{ "ok": false, "error": "<code>" }`.
- Client timeout 12 s; retry once after 1.5 s on network error.

### 5.2 Endpoints

| Method | action | Input | Output `data` | Errors |
|---|---|---|---|---|
| GET | `wishes` | – | `[{ name, message, ts }]` approved only, newest first, max 60 | – |
| GET | `rsvp` | `g` | `{ responses: [{event_id,status,pax,veg,jain,nonveg}], arrival:{mode,at}, message }` or `null` | `unknown_guest` |
| GET | `export` | `key` | `{ guests: { id: {n,s,e,p,l} } }` | `forbidden` |
| POST | `rsvp` | `{ g, responses:[{event_id,status,pax,veg,jain,nonveg}], arrival:{mode,at}, message }` | `{ saved: n }` | `unknown_guest`, `event_not_allowed`, `bad_pax`, `rsvp_closed` |
| POST | `wish` | `{ g, name, message }` | `{ pending: true }` | `unknown_guest`, `too_many` (max 3 per guest), `too_long` |
| POST | `open` | `{ g }` | `{}` | silent |
| POST | `admin.summary` | `{ password }` | see §8 | `forbidden` |
| POST | `admin.guests` | `{ password }` | full guest rows + their RSVP rows | `forbidden` |
| POST | `admin.markSent` | `{ password, g }` | `{}` | `forbidden` |
| POST | `admin.approveWish` | `{ password, wish_id, approved }` | `{}` | `forbidden` |

### 5.3 Code.gs requirements

- `doGet(e)` / `doPost(e)` route on `action`; unknown action → `bad_action`.
- Writes wrapped in `LockService.getScriptLock().waitLock(10000)`.
- Validate: guest exists; `event_id` ∈ guest's allowed events (or ALL); `0 ≤ pax ≤ max_pax`;
  integers; `veg+jain+nonveg == pax` when yes; strings trimmed and capped (name 60, message 500).
- **Formula-injection guard**: any string starting with `= + - @` is prefixed with `'` before
  writing to the Sheet.
- `wishes` GET cached with `CacheService` for 60 s; cache cleared on approve.
- Guest lookup: read Guests once per request into a map keyed by `guest_id`.
- Admin password compared against Script Property with a constant-time loop.
- Custom menu on `onOpen()`: **Shubh Vivah ▸ Generate missing guest IDs**, **▸ Publish guest list**
  (POSTs to `DEPLOY_HOOK_URL` via `UrlFetchApp`), **▸ Copy all invite links** (writes links to a
  "Links" tab).
- Timestamps written in IST (`Utilities.formatDate(new Date(), "Asia/Kolkata", "yyyy-MM-dd HH:mm:ss")`).
- `appsscript.json`: `"timeZone": "Asia/Kolkata"`, `"webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS" }`.

## 6. Edge function — `functions/_middleware.js`

```js
import guests from "./_data/guests.js";

export async function onRequest(ctx) {
  const url = new URL(ctx.request.url);
  const res = await ctx.next();
  const type = res.headers.get("content-type") || "";
  if (!type.includes("text/html") || url.pathname.startsWith("/admin")) return res;

  const id = url.searchParams.get("g");
  const guest = id && Object.prototype.hasOwnProperty.call(guests, id) ? guests[id] : null;
  // build title/description from guest (see table below)
  // HTMLRewriter:
  //   meta[property="og:title"], meta[name="twitter:title"]  -> setAttribute("content", title)
  //   meta[property="og:description"]                        -> setAttribute("content", desc)
  //   meta[property="og:url"]                                -> full URL incl. ?g=
  //   head (append)  -> <script id="guest-data" type="application/json">{json}</script>
  //                     JSON.stringify({ id, ...guest }).replace(/</g, "\\u003c")
  // headers: Cache-Control: no-cache ; X-Robots-Tag: noindex, nofollow
}
```

| Case | og:title | og:description |
|---|---|---|
| Known guest | `share.ogTitleKnown[guest.l]` with `{salutation}` = `s[l]`, `{name}` = `n[l]` (trim double spaces if no salutation) | `share.ogDescription[guest.l]` |
| No / unknown `g` | `share.ogTitleGeneric[defaultLang]` | `share.ogDescription[defaultLang]` |

Strings come from `wedding.json` → `share` block (imported into the function at build).

`index.html` head order (WhatsApp reads only the first part of the HTML):
1. `<meta charset>` 2. viewport 3. `<title>` 4. all `og:*` and `twitter:*` tags
5. `<meta name="robots" content="noindex,nofollow">` 6. preload of 2 critical fonts
7. everything else.
`og:image` is an absolute HTTPS URL to `/og/og-default.jpg` (1200×630, JPEG, < 300 KB), no redirect.

### 7.2 Boot sequence (`main.js`)

1. Import content; resolve guest (`guest.js`); resolve language: `localStorage.lang` → guest `l`
   → `wedding.defaultLang`.
2. Resolve phase (`time.js`): `pre` | `live` | `post`.
3. Render all sections into `<main>` (static DOM, final state, visible).
4. Mount opening gate overlay (only in `pre` and `live`; in `post` show thank-you hero instead).
5. `document.fonts.ready` → create animations → `ScrollTrigger.refresh()`.
6. Send `open` beacon (skip if `?preview=1`, which the admin page adds).
7. Lazy-load gallery images when within 1.5 screens.

### 7.4 Opening gate (signature moment)

DOM: fixed full-screen overlay `#gate` (use `100dvh`) containing `.door-left`, `.door-right`,
`.gate-light`, button `#gate-open`, button `#gate-skip`. Parent has `perspective: 1200px`.
Doors: each 50% width, `transform-origin` at outer edge, `backface-visibility: hidden`, artwork
`assets/svg/door-left.svg` / `door-right.svg` (fallback: CSS gradient doors with brass knobs).

Idle state: button text `wedding.gate.cta` ("स्पर्श करें" / "Tap to open"), breathing
`scale 1→1.04`, `ease.float`, `repeat -1, yoyo`, 1.8 s. Toran SVG at the top sways
`rotation ±1.5deg`, 3 s.

On tap (single GSAP timeline, total ≈ 5.2 s):

| t (s) | Action |
|---|---|
| 0.00 | `audio.unlock()`; play `shankh.mp3` (vol 0.9); `navigator.vibrate?.(40)` |
| 0.00 | Button fades out `dur.xs` |
| 0.25 | `.gate-light` (vertical gold gradient line, width 2px) scales `scaleX 1 → 60`, opacity 0 → 1, 0.9 s |
| 0.30 | Doors `rotateY: -105 / 105`, `dur.xl`, `ease.door` |
| 1.20 | Start shehnai loop, fade volume 0 → 0.35 over 3 s |
| 1.40 | Hero Ganesh SVG: `drawSVG: "0%" → "100%"` on all `path`s, 1.4 s, `stagger 0.02`, `power1.inOut` |
| 2.60 | Ganesh fill layer opacity 0 → 1 (gold), 0.6 s |
| 2.80 | `petals.start()` |
| 3.40 | Greeting SplitText chars: `opacity 0, y 12 → rest`, `stagger.chars` |
| 4.40 | Couple names (script font) — chars with `rotation -8 → 0`, `stagger 0.05` |
| 5.00 | Gate overlay `display:none`; `lenis.start()`; floating UI fades in |

Skip button (visible from t=0, low emphasis, top-right): jumps timeline to end
(`tl.progress(1)`), no sound. Reduced motion: no doors animation; tap fades the overlay
0.4 s and shows the final hero. If the guest scrolls/touches before tapping, nothing scrolls
(`lenis.stop()` + `overflow: hidden` on body) until the gate is opened or skipped.

### 7.5 Petals (`fx/petals.js`)

- One fixed `<canvas>` behind content, `pointer-events: none`, DPR capped at 2.
- Sprite atlas: 3 marigold petals + 2 rose petals drawn once to an offscreen canvas from
  `assets/svg/petal-*.svg` (or procedural ellipse fallback).
- Count: 36 normal, 16 on low-end (`device.js`: `hardwareConcurrency <= 4 || deviceMemory <= 3`
  or measured FPS < 45 over first 2 s → halve).
- Each petal: x random, y from -10%, fall speed 30–70 px/s, sway `sin(t*f)*amp` (amp 15–40 px),
  rotation 20–90 deg/s, 3D flip illusion by scaling x with `cos(t*r)`.
- API: `start()`, `stop()`, `burst(x, y, n=24)` (radial burst used by RSVP success and varmala).
- Pauses on `visibilitychange` hidden. Disabled for reduced motion (burst shows a static
  flower icon instead).

### 7.6 Haldi splash (`scenes/haldi.js`)

On the haldi event card entering at `top 70%`: a haldi-yellow layer
(`--haldi`) over the card goes `clip-path: circle(0% at 20% 30%)` → `circle(150% at 20% 30%)`,
0.9 s, `power2.out`, then the card content fades in over the yellow background; 6 small SVG
"splash drops" scale from 0 with `back.out(3)`. Once only.

### 7.7 Mehendi reveal (`scenes/mehendi.js`)

Mehendi card holds `assets/svg/mehendi-hand.svg` (stroke-only paths, ≤ 60 paths). Scrubbed with
scroll from `top 80%` to `center center`: `drawSVG 0%→100%`, `stagger 0.015`. The groom's
initial (from `wedding.json` couple.groom.initial) is placed as a `<text>` in the palm group and
revealed last with opacity. Stroke color `--mehendi` (#7A3E12).

### 7.8 Saat phere (`scenes/pheras.js`)

- Section pinned for `+=3500` px (`pin: true, scrub: 0.6`).
- SVG: agni kund in the center; an elliptical path `#phere-ring` around it; a diya icon on the
  path.
- `gsap.to("#diya", { motionPath: { path: "#phere-ring", align: "#phere-ring",
  alignOrigin: [0.5, 0.5], start: 0, end: 7 }, ease: "none" })` inside a scrubbed timeline
  (closed paths accept `end` > 1 to loop — verify on the GSAP MotionPath docs; if not, chain 7
  tweens `start: 0, end: 1`).
- Seven vachan labels at timeline positions `i/7`: current one fades/slides in centered below the
  kund, previous one fades out; a counter "Phera 3 / 7" in the utility font.
- Fire: 3 flame SVG layers with `scaleY` flicker (`sine.inOut`, random 0.3–0.6 s, repeat).
- At the end: all 7 vachan dots glow, text `wedding.phere.outro`.
- Reduced motion: no pin; the 7 vachans render as a numbered list.

### 7.10 RSVP (`scenes/rsvp.js`)

Form (one block per allowed event, only in `pre` phase and while `rsvp_open`):
- Status: segmented control Haan / Shayad / Nahi (`yes/maybe/no`), default none.
- If yes/maybe: pax stepper 1…`max_pax`; food split steppers Veg / Jain / Non-veg that must sum
  to pax (auto-fill all into Veg by default; show "Total must be N" inline if mismatched).
- "Same for all functions" link copies the first block's values to all.
- Shared fields: arrival mode (Car / Train / Flight / Local), arrival date-time (optional),
  message (optional, 500).
- On load: `GET rsvp` to prefill; show "Updated on …" if exists.
- Submit: optimistic success UI immediately (diya lights, `petals.burst`, text
  "Dhanyavaad! Hum aapka intezaar karenge"); POST in background; on failure show inline error
  with Retry, keep form values.
- Unknown guest (no `g`): RSVP block replaced by "Please use the personal link sent to you on
  WhatsApp" + contacts link.
- Deadline passed: show "RSVP closed on {date}, please call {contact}".

### 7.11 Fireworks (`fx/fireworks.js`)

Canvas, 5 rockets over 3 s, particles in gold/sindoor/ivory, gravity, fade. Runs once when
closing section is 60% visible. Skipped in reduced motion and on low-end.

### 7.12 Language toggle (`core/i18n.js`)

- `t(path)` reads `wedding.json` objects `{hi,en}`.
- Toggle swaps `lang` attribute on `<html>`, re-renders text nodes with `[data-i18n]`, crossfade
  0.25 s. Choice saved in `localStorage` (wrapped in try/catch).
- Fonts switch via `:lang(hi)` selectors (§9.2).

### 7.13 Calendar (`core/calendar.js`)

- Google Calendar link:
  `https://calendar.google.com/calendar/render?action=TEMPLATE&text=…&dates=YYYYMMDDTHHMMSSZ/YYYYMMDDTHHMMSSZ&details=…&location=…` (UTC).
- `.ics` for iPhone: build VCALENDAR text with `DTSTART;TZID=Asia/Kolkata`, create Blob, trigger
  download with a temporary `<a download>`.
- Button shows a small menu: "Google Calendar" / "Apple / Other (.ics)".

### 7.14 Maps

- Maps: `https://www.google.com/maps/search/?api=1&query={lat},{lng}` (or `mapsUrl` if given).
- Directions: `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}`.
- No iframes.

### 7.15 Shagun (`scenes/shagun.js`)

- Deep link: `upi://pay?pa={vpa}&pn={encodeURIComponent(name)}&cu=INR&tn={encodeURIComponent(note)}`
  (no amount).
- QR of the same string via `qrcode` → canvas, 220 px, margin 2, dark color `--ink`.
- VPA shown as text with Copy button.
- Copy on section: "Aapka aashirwad hi sabse bada shagun hai" (from json). Hidden if
  `shagun.enabled` false. Note in NOTES.md: some UPI apps restrict web deep links; QR scan is the
  reliable fallback — test on GPay, PhonePe, Paytm.

### 7.16 Phases (`core/time.js`)

- `live` = from 2 h before the first event start to 2 h after the last event end.
- `post` = after that.
- `?phase=pre|live|post` override works only in dev or with `?preview=1`.
- Live: gate still shows; `live.js` banner shows the event currently running (or next today),
  livestream link if set.
- Post: hero replaced with "Dhanyavaad" + couple photo + album link (`postWedding.albumUrl`);
  RSVP, countdown and shagun hidden; gallery and wishes stay.

## 9. Design system — Royal (laal–sona)

The invite is a designed object with one deliberate look (ivory paper, sindoor, gold). It does
**not** follow system dark mode. The admin page may use a plain light UI.

### 9.1 Color tokens (`src/styles/tokens.css`)

| Token | Hex | Use |
|---|---|---|
| `--paper` | `#FBF4E6` | page background |
| `--paper-2` | `#F4E7CC` | alternate section background |
| `--ink` | `#2A1612` | body text |
| `--ink-soft` | `#6B4A3F` | secondary text |
| `--sindoor` | `#A3161A` | primary accent, headings on paper |
| `--maroon` | `#5A0E12` | gate background, footer, dark sections |
| `--gold` | `#C9A043` | ornaments, dividers, buttons on maroon |
| `--gold-light` | `#E9D29A` | text on maroon |
| `--haldi` | `#F2B705` | haldi card and splash |
| `--mehendi` | `#7A3E12` | mehendi strokes |

Contrast: body text `--ink` on `--paper` and `--gold-light` on `--maroon` both pass WCAG AA.
Gold (`--gold`) is never used for body text on paper.

Paper texture: a subtle SVG noise (`feTurbulence`) as a fixed background at 4% opacity, generated
once as a data URI — not an image file.

### 9.2 Typography

| Role | Latin | Devanagari | Package |
|---|---|---|---|
| Couple names (script) | Great Vibes 400 | Yatra One 400 | `@fontsource/great-vibes`, `@fontsource/yatra-one` |
| Headings / display | Cinzel 500, 700 | Yatra One 400 | `@fontsource/cinzel` |
| Invitation prose | Cormorant Garamond 500, 600 italic | Tiro Devanagari Hindi 400 | `@fontsource/cormorant-garamond`, `@fontsource/tiro-devanagari-hindi` |
| UI (buttons, forms, labels, numbers) | Mukta 400, 600 | Mukta 400, 600 | `@fontsource/mukta` |

Import only the listed weights and the `latin` + `devanagari` subsets. Preload the two fonts used
above the fold (Yatra One + Great Vibes). `font-display: swap`.

Scale (mobile → desktop, via `clamp`):
names 44→72 px · h2 28→40 · h3 20→24 · prose 19→21 (line-height 1.7) · UI 15→16 ·
small caps labels 12 (letter-spacing 0.14em, uppercase for Latin only).
Numbers use `font-variant-numeric: tabular-nums`.

### 9.3 Layout

- Single column, max content width 560 px on mobile/tablet; on desktop (≥ 1024) the page sits
  in a centered 560 px "patrika" column with ornate side borders (like a physical card), so
  the design stays the same on every device.
- Section padding: `padding-block: clamp(64px, 12vw, 120px)`; side gutter 20 px.
- Section dividers: a centered ornament SVG (lotus / paisley) between sections.
- Alternating backgrounds `--paper` / `--paper-2`; phere and closing sections on `--maroon`.
- Buttons: pill, 48 px min height, `--sindoor` fill with `--paper` text; on maroon: `--gold`
  outline with `--gold-light` text. Focus ring: 3 px `--peacock` offset 2 px.
- Event card: arched top (CSS `border-radius: 999px 999px 16px 16px / 180px 180px 16px 16px`),
  `--line` border, motif icon in the arch.

### 9.4 Iconography

Line icons from `lucide` (MIT) — only: map-pin, navigation, calendar-plus, copy, phone,
message-circle, volume-2, volume-x, languages, check, x, chevron-down, image, gift. Import
individual SVGs, not the whole set.

### 9.5 Required owner assets (`assets/svg/`) — see MANUAL-STEPS.md for sourcing

| File | Spec |
|---|---|
| `ganesh-line.svg` | Stroke-only line art (no fills), 1–3 px stroke, ≤ 120 paths, viewBox square |
| `ganesh-fill.svg` | Same artwork, gold fill layer, aligned to the same viewBox |
| `door-left.svg`, `door-right.svg` | Carved temple door halves, portrait, maroon + brass |
| `toran.svg` | Marigold + mango-leaf toran strip, wide |
| `kalash.svg` | Small kalash ornament |
| `divider-lotus.svg` | Section divider ornament |
| `agni-kund.svg` | Fire altar, flames as 3 separate groups `#flame-1..3` |
| `diya.svg` | Small diya icon |
| `varmala-couple.svg` | Bride/groom silhouettes with garlands as groups `#garland-bride`, `#garland-groom` |
| `mehendi-hand.svg` | Stroke-only mehendi on hand outline |
| `petal-marigold-1..3.svg`, `petal-rose-1..2.svg` | Single petals |

All SVGs run through SVGO (`npx svgo`) and must be < 60 KB each (Ganesh < 80 KB).
Sourcing and preparation: see `ASSETS-AND-CONTENT.md`.

**Filled instead of stroked line art:** if `ganesh-line.svg` or `mehendi-hand.svg` arrives as
filled shapes (common after auto-tracing), use a **mask reveal**: wrap the artwork in a `<mask>`
whose content is 1–3 hand-authored thick stroke paths (stroke-width ≈ 6% of viewBox) roughly
following the figure; animate those mask strokes with DrawSVG. Visually identical "drawing"
effect, no need to re-trace.

**Procedural ornaments** (build in Phase 1, see ASSETS-AND-CONTENT §5): `src/fx/mandala.js`
(seeded 16-fold radial mandala, gold gradient strokes), lotus/paisley divider, kalash, diya
(flame as separate group), petals, jharokha arch frame, repeating toran fallback. These are
the fallbacks for any missing owner asset.
If a file is missing, the module uses a simple geometric fallback and logs a dev warning — never
blocks the build.

## 10. Performance, accessibility, compatibility

**Budget (fail the build if exceeded — `scripts/check-budget.mjs`):**

| Item | Limit |
|---|---|
| Initial JS (gzip) | 150 KB |
| Initial CSS (gzip) | 40 KB |
| Fonts total | 250 KB |
| SVGs above the fold | 200 KB |
| HTML | 30 KB |
| og-default.jpg | 300 KB |

Other rules:
- Photos: `<picture>` with AVIF → WebP → JPEG, `srcset` 480/960/1600, `loading="lazy"`,
  `decoding="async"`, explicit `width`/`height`.
- Audio: shehnai loop MP3 96 kbps mono, ≤ 1.2 MB, 60–90 s seamless loop; shankh ≤ 80 KB.
  Loaded only after the gate tap.
- `will-change` only during an active animation.
- Pause petals, fireworks, flicker loops when not visible (`IntersectionObserver` / ScrollTrigger
  `toggleActions`).
- Targets: LCP < 2.5 s on "Fast 4G" throttling, CLS < 0.05, 50+ fps on a 4 GB Android phone.

**Accessibility:** semantic landmarks; buttons are `<button>`; every form control has a `<label>`;
all images have `alt`; decorative SVGs `aria-hidden="true"`; SplitText uses its built-in
aria handling; color is never the only signal; min tap target 44 px; text scales with system
font size up to 130% without breaking layout.

**Compatibility checklist:** WhatsApp in-app browser (Android + iOS), Chrome Android, Samsung
Internet, Safari iOS 16+, Instagram in-app browser. Use `100dvh` with `100vh` fallback. iOS audio
only after a user gesture (gate tap). Test system font size "Large".

## 11. Security and privacy

- `public/robots.txt`: `User-agent: * / Disallow: /`; `_headers`: `X-Robots-Tag: noindex, nofollow`
  for `/*`; `Referrer-Policy: strict-origin-when-cross-origin`;
  `Permissions-Policy: camera=(), microphone=(), geolocation=()`.
- Guest IDs random (§4.2); unknown IDs get the generic invite, no error that confirms/denies IDs.
- Guest phone numbers only in Sheet and admin responses (contact people in `wedding.json` are
  public by design).
- Admin: password in Script Properties; every admin action re-checks it; wrong password → 1 s
  `Utilities.sleep` before responding.
- Wishes are moderated by default (`wishes_require_approval`).
- All inserted text via `textContent`.

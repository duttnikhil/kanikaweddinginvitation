## 1. Product summary

One URL per family: `https://<site>.pages.dev/?g=<guestId>`.

- WhatsApp preview shows the family's name in the title.
- Opening: temple doors open on tap, conch sound, Ganesh line-art draws itself, petals fall, the
  family's name and the couple's names reveal.
- Scrolling tells the invitation: parents' invitation text, couple, story, countdown, the
  functions this family is invited to, interactive rituals (saat phere, varmala, mehendi, haldi),
  gallery, RSVP per function, shagun (UPI), blessings wall, travel/stay, contacts, closing.
- The site changes by date: **pre** (invite), **live** (wedding days: "Now happening"),
  **post** (thank-you + photo album).
- Admins get `/admin/`: headcounts per function, food split, who opened, who hasn't replied,
  one-tap WhatsApp send per guest.

## 2. Architecture

```
Guest phone ──GET /?g=ID──▶ Cloudflare Pages
                              │ functions/_middleware.js
                              │  - looks up ID in bundled guest map (functions/_data/guests.js)
                              │  - rewrites og:title / og:description
                              │  - injects <script id="guest-data" type="application/json">
                              ▼
                           dist/index.html + assets (static, CDN)

Guest phone ──POST (rsvp / wish / open)──▶ Apps Script web app ──▶ Google Sheet
Admin page  ──POST (admin.*)────────────▶ Apps Script web app ──▶ Google Sheet

Sheet menu "Shubh Vivah ▸ Publish guest list" ──UrlFetch──▶ Cloudflare Deploy Hook
   └─▶ Cloudflare build runs `npm run sync-guests` (GET ?action=export) then `vite build`
```

Why the guest map is bundled into the edge function instead of fetched per request:
- Zero extra latency on page open and on WhatsApp's crawler (which times out quickly).
- Apps Script cold starts (1–2 s) never touch page load; Apps Script is used only for writes and
  admin.
- Files under `functions/` are not served as static assets, so the name list is not public.

## 4. Data

### 4.1 `content/wedding.json`

The full example with every field is in `content/wedding.json` (delivered alongside this spec).
Rules:
- Every text field is `{ "hi": "...", "en": "..." }`.
- All datetimes are ISO 8601 with `+05:30` offset.
- `events[].id` is one of: `tilak`, `haldi`, `mehendi`, `sangeet`, `baraat`, `phere`, `vidaai`,

- Optional blocks (`story`, `gallery`, `shagun`, `travel`, `livestream`, `postWedding`) are

## 5. API contract (Apps Script web app)

Single URL: `https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec` (stored in `.env` as
`VITE_API_URL` and in Cloudflare env as `APPS_SCRIPT_URL`).

### 5.1 Transport rules (important — avoids CORS failures)

- **GET**: query parameters, no custom headers.
- **POST**: `fetch(url, { method: "POST", body: JSON.stringify(payload),
  headers: { "Content-Type": "text/plain;charset=utf-8" }, redirect: "follow" })`.
  `text/plain` keeps it a "simple request" so the browser sends no preflight (Apps Script cannot
  answer OPTIONS). Code.gs reads `JSON.parse(e.postData.contents)`.
- **Open ping**: `navigator.sendBeacon(url, new Blob([json], { type: "text/plain" }))`, fire and
  forget.
- Every response: `ContentService.createTextOutput(JSON.stringify(obj)).setMimeType(JSON)`.
  Shape: `{ "ok": true, "data": ... }` or `{ "ok": false, "error": "<code>" }`.
- Client timeout 12 s; retry once after 1.5 s on network error.

### 5.2 Endpoints

| Method | action | Input | Output `data` | Errors |
|---|---|---|---|---|
| GET | `wishes` | – | `[{ name, message, ts }]` approved only, newest first, max 60 | – |
| GET | `rsvp` | `g` | `{ responses: [{event_id,status,pax,veg,jain,nonveg}], arrival:{mode,at}, message }` or `null` | `unknown_guest` |
| GET | `export` | `key` | `{ guests: { id: {n,s,e,p,l} } }` | `forbidden` |
| POST | `rsvp` | `{ g, responses:[{event_id,status,pax,veg,jain,nonveg}], arrival:{mode,at}, message }` | `{ saved: n }` | `unknown_guest`, `event_not_allowed`, `bad_pax`, `rsvp_closed` |
| POST | `wish` | `{ g, name, message }` | `{ pending: true }` | `unknown_guest`, `too_many` (max 3 per guest), `too_long` |
| POST | `open` | `{ g }` | `{}` | silent |
| POST | `admin.summary` | `{ password }` | see §8 | `forbidden` |
| POST | `admin.guests` | `{ password }` | full guest rows + their RSVP rows | `forbidden` |
| POST | `admin.markSent` | `{ password, g }` | `{}` | `forbidden` |
| POST | `admin.approveWish` | `{ password, wish_id, approved }` | `{}` | `forbidden` |

### 5.3 Code.gs requirements

- `doGet(e)` / `doPost(e)` route on `action`; unknown action → `bad_action`.
- Writes wrapped in `LockService.getScriptLock().waitLock(10000)`.
- Validate: guest exists; `event_id` ∈ guest's allowed events (or ALL); `0 ≤ pax ≤ max_pax`;
  integers; `veg+jain+nonveg == pax` when yes; strings trimmed and capped (name 60, message 500).
- **Formula-injection guard**: any string starting with `= + - @` is prefixed with `'` before
  writing to the Sheet.
- `wishes` GET cached with `CacheService` for 60 s; cache cleared on approve.
- Guest lookup: read Guests once per request into a map keyed by `guest_id`.
- Admin password compared against Script Property with a constant-time loop.
- Custom menu on `onOpen()`: **Shubh Vivah ▸ Generate missing guest IDs**, **▸ Publish guest list**
  (POSTs to `DEPLOY_HOOK_URL` via `UrlFetchApp`), **▸ Copy all invite links** (writes links to a
  "Links" tab).
- Timestamps written in IST (`Utilities.formatDate(new Date(), "Asia/Kolkata", "yyyy-MM-dd HH:mm:ss")`).
- `appsscript.json`: `"timeZone": "Asia/Kolkata"`, `"webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS" }`.

## 6. Edge function — `functions/_middleware.js`

```js
import guests from "./_data/guests.js";

export async function onRequest(ctx) {
  const url = new URL(ctx.request.url);
  const res = await ctx.next();
  const type = res.headers.get("content-type") || "";
  if (!type.includes("text/html") || url.pathname.startsWith("/admin")) return res;

  const id = url.searchParams.get("g");
  const guest = id && Object.prototype.hasOwnProperty.call(guests, id) ? guests[id] : null;
  // build title/description from guest (see table below)
  // HTMLRewriter:
  //   meta[property="og:title"], meta[name="twitter:title"]  -> setAttribute("content", title)
  //   meta[property="og:description"]                        -> setAttribute("content", desc)
  //   meta[property="og:url"]                                -> full URL incl. ?g=
  //   head (append)  -> <script id="guest-data" type="application/json">{json}</script>
  //                     JSON.stringify({ id, ...guest }).replace(/</g, "\\u003c")
  // headers: Cache-Control: no-cache ; X-Robots-Tag: noindex, nofollow
}
```

| Case | og:title | og:description |
|---|---|---|
| Known guest | `share.ogTitleKnown[guest.l]` with `{salutation}` = `s[l]`, `{name}` = `n[l]` (trim double spaces if no salutation) | `share.ogDescription[guest.l]` |
| No / unknown `g` | `share.ogTitleGeneric[defaultLang]` | `share.ogDescription[defaultLang]` |

Strings come from `wedding.json` → `share` block (imported into the function at build).

`index.html` head order (WhatsApp reads only the first part of the HTML):
1. `<meta charset>` 2. viewport 3. `<title>` 4. all `og:*` and `twitter:*` tags
5. `<meta name="robots" content="noindex,nofollow">` 6. preload of 2 critical fonts
7. everything else.
`og:image` is an absolute HTTPS URL to `/og/og-default.jpg` (1200×630, JPEG, < 300 KB), no redirect.

### 7.2 Boot sequence (`main.js`)

1. Import content; resolve guest (`guest.js`); resolve language: `localStorage.lang` → guest `l`
   → `wedding.defaultLang`.
2. Resolve phase (`time.js`): `pre` | `live` | `post`.
3. Render all sections into `<main>` (static DOM, final state, visible).
4. Mount opening gate overlay (only in `pre` and `live`; in `post` show thank-you hero instead).
5. `document.fonts.ready` → create animations → `ScrollTrigger.refresh()`.
6. Send `open` beacon (skip if `?preview=1`, which the admin page adds).

### 7.4 Opening gate: envelope + wax seal (signature moment)

An ivory envelope resting on a cool linen backdrop, heart-shaped gold wax seal on the tip of
the top flap, "Tap to open" under it, tagline above. Tapping lifts the seal, the top flap swings
open on its hinge (3D) showing a gold-lattice liner, the card slides up out of the pocket, the
envelope drops away and the card grows to fill the screen and becomes the hero.

The gate is pre-rendered into `index.html` at build time (`gateMarkup()` in `fx/envelope.js`)
so it paints before any JS; `scenes/opening.js` adopts it. `#gate` is fixed, `100dvh`. The
envelope is `--ew × --eh` (`min(84vw, 360px, 44dvh)`, ratio 1.2) so the opened flap still fits
above it on short phones. Layers:

1. `.gate-bg`: deep wine `#3B1018` with a faint gold ogee jaali, a warm light pool behind the
   envelope, vignette, grain; a thin inset gold frame and gold filigree corners. Tagline and CTA
   in gold/ivory. The envelope's flap edges are gold foil (gradient stroke).
2. `.gate-top`: divider + `gate.tagline` (last word on its own line in the script font).
3. `.env` (`perspective: 1400px`), back → front:
   - `.env-back`: inside of the envelope, with the envelope's static drop shadow.
   - `.env-card`: the invitation card: names `{bride} {hero.joiner} {groom}` (bride first), no date
     (revealed on Save the Date). With `assets/img/hero-frame.*` the card is that artwork (same
     `border-image` as the hero, so it grows into the hero); without it, paper + double gold
     hairline + laurel monogram.
   - `.env-pocket`: side flaps + bottom flap (inline SVG, gradients, static `feDropShadow`, grain),
     with the addressee printed on it for personal links: `gate.to` + salutation + name
     ("Specially for Shri & Smt. Verma Parivar"); hidden on the generic link.
   - `.env-flap`: top flap, `transform-origin` top, `preserve-3d`; outside face = paper, inside
     face (`rotateX(180deg)`, `backface-visibility: hidden`) = dusty-blue liner with a gold ogee
     lattice, or `assets/img/envelope-scene.*` clipped to the liner triangle if supplied.
4. `.seal` (`#gate-open` button): heart wax seal, pure SVG, 80 px, muted antique gold
   (`#F1DFAE → #C9A45A → #7E5E22`), static turbulence wax edge, embossed ring, laurel, engraved
   "K | A". Idle: shine band every 3 s, seal "breathes" `scale 1 → 1.03`. The envelope is still.
5. `.gate-cta` under the envelope (opacity pulse); `#gate-skip` top-right from the start.

Tap on the seal or anywhere on the gate (except Skip). One GSAP timeline, ≈ 3.65 s:

| t (s) | Action |
|---|---|
| 0.00 | `audio.unlock()`; `seal-crack.mp3` (skipped if missing); `vibrate(30)`; seal press `scale → 0.94` |
| 0.10 | CTA + tagline fade out |
| 0.12 | Seal lifts off: `y -16`, `scale 1.05`, opacity 0, 0.5 s |
| 0.45 | Flap `rotationX 0 → 180`, 0.9 s `power2.inOut`; at 0.9 (past 90°) it goes behind the card (`zIndex`) |
| 1.10 | Card `yPercent → -58` out of the pocket, 0.85 s `power3.inOut` |
| 1.95 | Back, pocket, flap drop `y +75vh`, 0.75 s `power2.in` |
| 2.05 | Card content fades; card moves to the centre and scales to cover the viewport, 0.75 s |
| 2.10 | Backdrop fades |
| 2.35–2.90 | Page shown under the card; shehnai + `petals.start()`; gate fades out (0.45 s) |
| 2.45 | Hero: invocation, wreath DrawSVG, names SplitText, subtitle, ticket, greeting + scene; with `assets/img/hero-frame-frames/` the owner's animation plays once over the card (`fx/frame-anim.js`: top band = bells, bottom band = procession, 10 frames at ≈ 7 fps, sprites stepped with `transform`), then the overlay is removed (the static card is the last frame) |
| 3.65 | `#gate` removed, `lenis.start()`, floating UI fades in |

Only `transform`/`opacity` are animated (the flap's rotateX included); every shadow and filter is static.
Skip jumps to the end (no sound before a tap). Scroll is locked until opened. Reduced
motion: tap → seal fades, envelope fades, final hero. A tap before the app JS has loaded is
remembered (`boot.js`) and replayed. No `seal-crack.mp3` → silent; no shehnai → no music button.

### 7.5 Petals (`fx/petals.js`)

- One fixed `<canvas>` behind content, `pointer-events: none`, DPR capped at 2.
- Sprite atlas: 3 marigold petals + 2 rose petals drawn once to an offscreen canvas from
  `assets/svg/petal-*.svg` (or procedural ellipse fallback).
- Count: 36 normal, 16 on low-end (`device.js`: `hardwareConcurrency <= 4 || deviceMemory <= 3`
  or measured FPS < 45 over first 2 s → halve).
- Each petal: x random, y from -10%, fall speed 30–70 px/s, sway `sin(t*f)*amp` (amp 15–40 px),
  rotation 20–90 deg/s, 3D flip illusion by scaling x with `cos(t*r)`.
- API: `start()`, `stop()`, `burst(x, y, n=24)` (radial burst used by RSVP success and varmala).
- Pauses on `visibilitychange` hidden. Disabled for reduced motion (burst shows a static
  flower icon instead).

## 9. Design system — Watercolor Ivory

The invite is a designed object with one deliberate look (ivory paper, watercolor washes,
antique gold, navy slate text). It does **not** follow system dark mode. The admin page may
use a plain light UI.

## 10. Performance, accessibility, compatibility

**Budget (fail the build if exceeded — `scripts/check-budget.mjs`):**

| Item | Limit |
|---|---|
| Initial JS (gzip) | 150 KB |
| Initial CSS (gzip) | 40 KB |
| Fonts total | 250 KB |
| SVGs above the fold | 200 KB |
| First load incl. above-the-fold artwork (JS+CSS+HTML+fonts+scene+arch) | 1.8 MB |
| HTML | 30 KB |
| og-default.jpg | 300 KB |

Other rules:
- Photos: `<picture>` with AVIF → WebP → JPEG, `srcset` 480/960/1600, `loading="lazy"`,
  `decoding="async"`, explicit `width`/`height`.
- Audio: shehnai loop MP3 96 kbps mono, ≤ 1.2 MB, 60–90 s seamless loop; shankh ≤ 80 KB.
  Loaded only after the gate tap.
- `will-change` only during an active animation.
- Pause petals, fireworks, flicker loops when not visible (`IntersectionObserver` / ScrollTrigger
  `toggleActions`).
- Targets: LCP < 2.5 s on "Fast 4G" throttling, CLS < 0.05, 50+ fps on a 4 GB Android phone.

**Accessibility:** semantic landmarks; buttons are `<button>`; every form control has a `<label>`;
all images have `alt`; decorative SVGs `aria-hidden="true"`; SplitText uses its built-in
aria handling; color is never the only signal; min tap target 44 px; text scales with system
font size up to 130% without breaking layout.

**Compatibility checklist:** WhatsApp in-app browser (Android + iOS), Chrome Android, Samsung
Internet, Safari iOS 16+, Instagram in-app browser. Use `100dvh` with `100vh` fallback. iOS audio
only after a user gesture (gate tap). Test system font size "Large".

## 11. Security and privacy

- `public/robots.txt`: `User-agent: * / Disallow: /`; `_headers`: `X-Robots-Tag: noindex, nofollow`
  for `/*`; `Referrer-Policy: strict-origin-when-cross-origin`;
  `Permissions-Policy: camera=(), microphone=(), geolocation=()`.
- Guest IDs random (§4.2); unknown IDs get the generic invite, no error that confirms/denies IDs.
- Guest phone numbers only in Sheet and admin responses (contact people in `wedding.json` are
  public by design).
- Admin: password in Script Properties; every admin action re-checks it; wrong password → 1 s
  `Utilities.sleep` before responding.
- Wishes are moderated by default (`wishes_require_approval`).
- All inserted text via `textContent`.
